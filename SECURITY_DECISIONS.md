## SD-001 — Credential committed to a public repository

**Date recorded:** 2026-09-25
**Raised by:** Security audit of the repository (11-repository review)
**Decision owner:** Hatem Ismail Shalaby (repository owner)

### What was found

| Field | Value |
|---|---|
| File | `.env` |
| Committed in | `a78d5d8` — "Add files via upload" |
| Exposure | Public repository; the file is present in the git history and in `HEAD` |
| Content class | Database host, port, name, user, and a plaintext password |
| Related | `docker-compose.yml` line 7 held a plaintext `POSTGRES_PASSWORD` value |

The file was committed because the repository's `.gitignore` at the time was the
one generated by `python -m venv`, whose only rule is `*`. The files were added
through the GitHub web upload interface, which does not consult `.gitignore`.
The ignore rule was therefore never in a position to prevent the commit.

### Decision

The repository owner confirmed on 2026-09-25 that **the exposed credential has
already been rotated**. The value that was committed is no longer valid.

Acting on that confirmation, the following changes were made:

1. `.env` was removed from the repository index and from the working tree.
2. `docker-compose.yml` no longer carries a literal password. The value is now
   supplied by the environment at run time, and the compose file fails closed if
   the variable is absent.
3. `.gitignore` was replaced with a rule set that covers `.env`, key material,
   credential files, virtual environments, and local outputs.
4. `.env.example` was added, containing placeholders only.

### What this decision does not fix

Removing a file from the current commit does **not** remove it from history. The
blob remains reachable from `a78d5d8`. Anyone who cloned the repository before
2026-09-25 still holds it.

Because the credential has been rotated, the residual risk is limited to
information disclosure — the database host, port, name, and username, plus
knowledge of the password format the owner uses elsewhere. That format is the
material concern: a pattern reused across services is a lateral-movement risk
even after one instance is rotated.

### Standing rule adopted

No credential value enters a repository. Configuration is read from the
environment. Example files carry placeholders only. A repository's `.gitignore`
must be authored deliberately — never inherited from a tool that generates one
as a side effect.
